# The render kit (renders v2, WP-0)

Package `com.nateyburr.beyondthestars.client.render`, client only. Spec: the design repo's
`designs/docs/renders-v2.md` §2-§4. Every big render (the Kerr hole, the quasar, the Eye's centre object, and the
new renders of WP-1..WP-8) draws through it.

## Programs and GLSL

| Piece | What it does |
|---|---|
| `BTSShaders` | Registry of every program. `program(label, recipe)` registers a GT `ShaderRecipe`; `Program.get()` bakes it lazily (GT's `ShaderProfile` picks the legacy `#version 120` or the Angelica core `#version 330` variant) and returns null when it does not bake: the object then draws its fixed-function path. A dead program logs one line and stays dead until the next resource reload (`markReload`, hooked to GT's `RenderInit.onResourceReload`). `Program.mesh(builder)` owns a VBO built against the program's vertex format, rebuilt after each bake. |
| `GlslSourcePack` | Serves our sources to GT under the resource domain `beyondthestars_glsl`: reads `assets/beyondthestars/shaders/<file>`, expands `#include "lib/x.glsl"` (each file once, recursively, followed by a `#line`), and after the `#version` line defines `BTS_TEX` (`texture2D` / `texture`) and, for `.330.glsl` files, `BTS_CORE`. Added to the live resource manager on first bake. |
| `shaders/lib/*.glsl` | `common` (hashes, smoothstep), `noise` (texture value noise 2D / 3D, fbm, ALU noise, cells), `blackbody` (LUT lookup + analytic fallback), `tonemap` (the soft shoulder `1 - exp(-k c)`, luma, hot-white), `glow` (glow sprite falloff, soft point). Includes declare no uniforms; samplers are passed as arguments. |
| `NoiseTex` | The two shared textures: 256 x 256 RGBA noise (repeat, linear; G = R shifted by (37, 17) for `btsNoise3`) on unit 4 and the 256 x 1 blackbody LUT (1,000-40,000 K, log scale) on unit 5. `bind()` / `unbind(was)` restore the previous bindings. |
| `Blackbody` | Planck x CIE 1964 10-degree, display sRGB with max channel 1. CPU colours for the fixed paths and the LUT texels. |

A new program: add `shaders/<name>.vert.glsl`, `.frag.glsl` (120) and `.vert.330.glsl`, `.frag.330.glsl` (core),
then

```java
private static final ShaderRecipe RECIPE = BTSShaders.recipe("<name>")
    .required("u_Color")
    .sampler("u_Noise", NoiseTex.NOISE_UNIT)
    .modelUniform("u_ModelMatrix") // legacy: gl_ModelViewProjectionMatrix * u_ModelMatrix; core: u_MVP
    .attribute("a_Position", VertexAttribute.POSITION)
    .attribute("a_UV", VertexAttribute.UV);
static final BTSShaders.Program PROGRAM = BTSShaders.program("<name>", RECIPE);
static final BTSShaders.Mesh QUAD = PROGRAM.mesh(Meshes::quad);
```

Every uniform a recipe declares must be used in both variants (GT refuses the bake otherwise).

## Quality, LOD and the budget

| Piece | What it does |
|---|---|
| `RenderQuality.tier(key, radius, distance, programs...)` | The object's tier this frame: `FIXED` (today's fixed-function render) for `renderQuality=low`, a context without GL 2.1 + VBOs, a program that does not bake, or a GL error after the object's draw (checked once a second in a dev environment or with `-Dbts.render.glcheck=true`); else the LOD tier. `medium` never draws L0; only the `renderMaxHighObjects` largest objects on screen (last frame's ranking) may draw L0. |
| `Lod` | Projected radius `R / d x (H / 2) / tan(fov / 2)` (FOV from the projection matrix, once per frame); tiers L0 > 300 px, L1 > 80, L2 > 20, L3 below, x `renderLodScale`, 10 % hysteresis. |
| `ShaderpackProbe` | Reflective: is an Iris / Angelica shaderpack in use (cached a second). `RenderQuality.backgroundLensing(tier)` asks it. |
| Config (`client_render`) | `renderQuality` (high), `renderLodScale` (1.0), `renderMaxHighObjects` (2), `renderBackgroundLensing` (true), `renderParticles` (true). The old switches (`eyeRenderCentre`, `renderKerrHole`, `renderQuasar`, GUI switches) still win. |

## Drawing helpers

| Piece | What it does |
|---|---|
| `GlSave` | Captures and restores the GL state a layer touches (blend + function, depth test + mask, alpha test, cull + mode + front face, lighting, fog, shade model, texturing on unit 0 and the lightmap unit). No `glPushAttrib` (Angelica's core profile has none). |
| `Layers` | `untextured()`, `additive()` (fixed-function layers), `emissive()` (shader layers: lightmap 240, additive, no depth writes). Each returns the `GlSave` to restore. |
| `FixedShapes` | The LOW path's shapes, moved unchanged from the Eye: `ring`, `rimShell`, `sphere` (per-corner N.V alpha), `outside`, `billboardQuad`. |
| `Billboard` | Camera-facing axes at a camera-relative point; `model(...)` maps the unit quad onto it. |
| `Meshes` | VBO meshes: unit quad, UV sphere, unit annulus (the shader places radius `mix(r0, r1, uv.x)`), ribbon. |
| `GlowSprite` | `draw(...)`: the `bts_glow` program (Gaussian core + halo through the shoulder); `drawFixed(...)`: today's linear disc. |
| `BlackHoleLens` | The shared black-hole program `bts_blackhole` (GLSL `shaders/bh/lens.glsl`, spec §5.2): one camera-facing quad; each fragment traces its view ray backwards through the hole (Schwarzschild bending in Binet form, leapfrog steps of `k x r`, plus a weak gravitomagnetic term for the Kerr D-shape) and integrates a thin Gaussian disc slab on the way (exact column per step, so the edge-on disc and the lensed arcs come from the same march). Doppler beaming and gravitational redshift per crossing, Keplerian-sheared cylinder noise for the filaments and hot clumps (two 7.2 s cycles cross-faded, so the gas shears but never winds up), a photon ring from the rays bent by about half a turn, opening / Hawking flash rings. Premultiplied alpha, depth test without depth writes; empty fragments discard; a second draw of the quad (colour writes off, `u_Lens.w` = 1: no screen copy, L3's 14-step march with one octave, stopping once alpha reaches 0.05; inside b < 3.1 r_s, the shadow and the photon ring, seen from outside the photon sphere, no march at all) writes depth where the hole has a body (alpha 0.05 and up; the glow and the photon-ring halo add light, never alpha), so the shadow and the disc hide later glass, water, rain or particles behind them while the faint glow no longer does (`-Dbts.render.bhDepthDebug=true` shows that pass in red). Steps / step size / octaves per tier: L0 72 / 0.11 / 4, L1 32 / 0.20 / 3, L2 24 / 0.28 / 2, L3 14 / 0.40 / 1; at most 4 gas samples per ray, plane heights checked before the disc transform, and a ray leaving past 3 r_s clear of the disc stops early (not at L0, whose screen copy wants the final direction). Bounding sphere 1.08 x the disc's outer edge. A renderer fills a `Params` (size in blocks per r_s, disc edges, temperature, turbulence, streamers, tilt, flashes). |
| Quasar (`machines/quasar/render/QuasarFx`, WP-2) | Three programs of the quasar's own (spec §6): `bts_qring` (GLSL `shaders/quasar/ring.glsl`), the accretion ring as a **ray-marched volume** inside a slab proxy (top and bottom faces, inner and outer walls; the vertex shader places them from the radii, each front-facing fragment marches from where its ray enters to where it leaves, a quad in front of the camera covers a camera standing inside the slab). The march takes at most 16 / 12 / 8 / 6 sub-segments per tier, each at least two gas half-thicknesses long, samples the gas where the sub-segment comes nearest the plane and integrates the Gaussian height profile through it exactly (erf), so there is no step banding and no noise lookup away from the plane; noise octaves finer than the sample's footprint (its horizontal reach, or a pixel stretched by the grazing angle) fade out. `bts_qjet` (`quasar/jet.glsl`): a jet on the shared ribbon turned about its axis to the camera: core, two helical strands, knots on a hashed launch schedule, sheath, terminal bow. `bts_qfx` (`quasar/fx.glsl`): one program, three meshes chosen by a mode uniform: 12 dipole field lines (camera-facing ribbons placed in the vertex shader), 64 debris sprites (positions from a seed and the event clock, no CPU particles) and the shock shell (the shared sphere, rim-bright, noise-broken). Draw order: ring, the far jet and the far halves of the field lines and shell, then the hole (`BlackHoleLens`, depth writes where it has a body, its L0 screen copy holds the ring and the far jet), then the near halves, glows and debris. |
| Eye stars (`machines/eye/render/EyeStarFx`, WP-3 / WP-4) | Three programs (spec §7, §8), GLSL `shaders/star/`. `bts_star` (`star/surface.glsl`): the photosphere on a 64 x 32 sphere 1.2 % larger than the star; each fragment intersects its view ray with the true sphere (a perfect silhouette) and shades in 3D object space (no seams): granulation from 3D cellular noise (2 x 2 x 2 cells, feature points wandering so the granules boil) at one or two scales plus fbm mesogranulation, sunspots with filamented penumbrae and faculae toward the limb, a giant's 5-8 convection cells, a protostar's blotches, the neutron star's polar hot spots seen through light bending (Beloborodov: about 74 % of its surface shows), the cooling dwarf's convective mottling and the black dwarf's hexagonal crystal sheen, the magnetar's glowing crust faults; quadratic limb darkening with a cooler limb; colour from the blackbody LUT with the display temperature below 6,000 K pulled down by up to 38 % (a Sun-like star reads golden, not white); detail fades by the pixel's footprint (`fwidth`). Opaque, writes depth (pass 0). `bts_starhalo` (`star/halo.glsl`): one quad just in front of the star (or 0.3 blocks in front of the camera inside the cavity) whose fragments integrate their rays analytically, the star cut by a ray / sphere test: glow, corona streamers (3D noise on the ray's offset direction, stretched radially, densest round the equator), a giant's haze and mass-loss wisps, a protostar's absorbing cocoon (clearing from the poles), its dusty disc and bipolar outflows, the lighthouse beams (closest approach of the ray to each axis, brighter down the line of sight, a flash when one points at the camera), the magnetosphere, two thin shells (rim-weighted path length; shock fronts with Rayleigh-Taylor fingers, the supernova remnant's filaments over a synchrotron haze, flares, flashes). Premultiplied (`ONE, ONE_MINUS_SRC_ALPHA`, pass 1; alpha = the dust's absorption). `bts_starlines` (`star/lines.glsl`): 16 camera-facing ribbon loops placed in the vertex shader, never thinner than about a pixel and a half: dipole field lines (twisted, crackling, torn open by a giant flare) or prominences (rising and draining, turning with the surface). Detail: L0 three noise scales, L1 two, L2 one and no loops, L3 the plain photosphere plus a glow sprite; capped by the photosphere's own size on screen. The galaxies (T7, T8, planets) draw through `GalaxyFx` (WP-5); FIXED draws today's look. Up to 3 draw calls. |
| Eye galaxies (`machines/eye/render/GalaxyFx`, WP-5) | Four programs (spec §9), GLSL `shaders/galaxy/`. `galaxy/lib.glsl` is the model the stars and the disc share: a flat rotation curve quantised to whole turns per hour (the hour-long clock wraps without a jump), trailing log-spiral ridges turning rigidly with the pattern angle, young light born on a ridge and fading downstream, dust just upstream of it, old stars bunched toward it by a phase compression of their orbits (no winding up). `bts_galpts` (`galaxy/points_vert.glsl`): static `GL_POINTS` buffers (20,000 stars per galaxy: old disc, young, bulge, the Milky Way's bar and Magellanic Clouds, star-forming clusters reborn every 180 s on an arm and sheared into short arcs with their pink H II glows, the halo and globulars; 3,000 for the Galactic Merger's companion, 1,500 for the dwarf of a minor merger or a satellite crossing, 2,000 for the tidal tails and the bridge); each star's motion, brightness, its settling during the Magnetar Collapse's halo capture and its dimming by the dust between it and the eye are computed in the vertex shader; round sprites with faint diffraction spikes on the largest. Buffers are shuffled, so LOD draws a prefix. `bts_galdisc` (`galaxy/disc.glsl`): one quad in front of the galaxy whose fragments follow their rays through the disc frame: the exponential disc and arms, young light, H II knots and dust lanes (four noise fields from one RGBA lookup per octave) integrated over sub-segments of the star slab (the Gaussian height profiles of the stars and the thinner dust exactly, so face-on rays need one or two and edge-on ones up to 12), the bulge and bar as ellipsoidal Gaussians (erf), split by the dust, the companion's and dwarf's cores, the ring wave, starbursts and the collapse flash and shell. Premultiplied; alpha = the dust's absorption. `bts_galsky` (`galaxy/sky.glsl`): the dark backdrop on the far side of a radius-20 sphere (front faces culled), nebula and sparse stars, alpha 0.5 at night to 0.82 at noon, fading where the sphere turns edge-on and above / below the core band's height. `bts_galplan` (`galaxy/planets.glsl`, planets mode): one quad, each ray intersects up to nine analytic planets on Keplerian orbits (lit toward the sun with a soft terminator; rocky, veiled, ocean world with clouds, desert, banded giant with a storm, ringed giant with the planet's shadow on its rings, ice giants) and the faint orbit lines; the sun is `EyeStarFx.sunLook` (a calm Sol on the star programs). Detail: L0 12 sub-segments, 3 noise octaves, every star; L1 7, 2, half; L2 3, 1, 15 %; L3 a glow sprite. Up to 6 draw calls (backdrop, disc, galaxy stars, or both galaxies' during the merger, companion, dwarf, tails). |
| Machines (`client/render/MachineFx`, `MachineFrame`, `DeferredDraws`; WP-6..WP-8) | The renders of the machines without a render tile (spec §10-§12), drawn from GT's `IMTERenderer` hook in each controller (`MTEHomogeny`, `MTERealityBase`, `MTEConduitElement`, `MTEBurstThermaliserCrown`) with their inputs on GT's render-data channel (`encodeRenderData` / `decodeRenderData`, sent every 1-2 s, never saved). `MachineFrame` places the mockup's voxel frame (`designs/voxel.js`) in the world from the controller: the manifest's `turns` and `centre.rel`, so shapes are written in mockup coordinates. GT calls `renderTESR` in pass 0 only, before TecTech's Quantum Glass (a pass-1 blended block) which then swallowed most of the glow, so each hook only queues its draw in `DeferredDraws`, run from `RenderWorldLastEvent` after the translucent pass. Three programs: `bts_mvol` (GLSL `fx/vol.glsl`): a ray-marched volume in an elliptic cylinder, only its back faces shade (each fragment intersects its ray with the cylinder analytically, so blocks in front of the volume hide it through the depth test); mode 0 the Homogeny's vortex (braids, sheath, core thread; the shear helix's glow evaluated once at each wall crossing, the march only through the funnel r < 10.8), mode 1 a Diffraction drum (region clouds or the medium marched; the lens's rainbow fans and the floor fringes as analytic sheets where the ray crosses their planes), mode 2 the Diffraction spine (beam and lenses); interleaved-gradient-noise dither. `bts_beam` (`fx/beam.glsl`): a camera-facing ribbon along a quadratic Bezier curve given camera-relative (core, sheath, two helical strands, knots on a hashed launch schedule, fades at both ends, never thinner than about a pixel and a half). `bts_mfx` (`fx/mfx.glsl`): mode 0 a field shell (Fresnel rim, hexagonal cells), 1 a holographic glyph ring on the shared annulus, 2 reassembling voxel sprites placed in the vertex shader from a seed and the clock, 3 a portal disc (bent starfield and nebula inside a rim; premultiplied, it hides what is behind it). Volume steps per tier: vortex 12 / 9 / 6, drums 8 / 6 / 4, spine 10 / 8 / 6; L3 a glow sprite; FIXED draws nothing (these machines drew nothing before v2). Client keys `renderHomogeny`, `renderReality`, `renderConduit`. Harness overrides: `HomogenyRender.debugLook`, `RealityRender.debugLook`, `ConduitRender.debugLook` (a 4-entry case look ending in -2). |
| `OpaqueDepth` (R-16) | Under Angelica only: Celeritas writes the translucent glass into the depth buffer, which hid every machine render drawn after the translucent pass behind TecTech's glass. The depth is saved when the first machine queues its draw (pass 0), put back for the deferred draws and restored after them (three depth blits through two depth-only framebuffers in the main framebuffer's depth format). With a shaderpack or without GL 3.0 the machines draw at once in pass 0. A machine queues only when it can draw a shader tier (`RenderQuality.mayShade`: quality above low, a capable context, its programs baked, no GL-error fallback) and has something to show (a conduit element only with a stream or a mouth's portal, a crown only with a stream), so LOW and idle machines never pay for the blits. `-Dbts.render.opaqueDepth=false` / `-Dbts.render.machineImmediate=true` for checks. |
| `FrameCopy` | The screen copy a black hole bends at L0 (§4.3): one display-sized texture on unit 6, `glCopyTexSubImage2D` of the quad's screen rectangle at the same offsets, so the shader samples it with screen coordinates. Only when `RenderQuality.backgroundLensing` (L0, `renderBackgroundLensing`, no shaderpack). |
| `PointBatch` | A static `GL_POINTS` VBO (position, size in blocks, packed colour) drawn by `bts_points` with distance-scaled `gl_PointSize` and soft round sprites; `drawFixed` draws a subset as billboard quads. |
| `RenderClock` | `u_Time` seconds, `(totalWorldTime % 72,000 + partialTicks) / 20`. |
| `RenderFrame` | Frame counter and the per-frame hooks (LOD ranking, GPU timer). |

## Dev switches

| Switch | Effect |
|---|---|
| `-Dbts.rendertest.quality=low\|medium\|high` | Overrides `renderQuality` (the harness shoots all three). |
| `-Dbts.rendertest.gputime=true` | `GpuTimer`: `GL_TIME_ELAPSED` queries round each renderer, read back without stalling; the harness writes `gpu_ms`, `cpu_ms` and `gpu_detail` (per renderer, ms per frame over the view's still window) to `fps.tsv` and logs each object's tier. |
| `-Dbts.render.failShaders=true` | Every registered program reports dead: shoot the fallback paths. |
| `-Dbts.render.selftest=true` | `KitSelfTest`: compiles and links both profiles of every kit program from the served sources, logs each bake, writes `kit-noise.png` / `kit-lut.png`, and draws a test panel in front of the camera (the self-test program as baked and as a hand-linked core variant, glow and points by shader and by fixed function, the two textures). |
| `-Dbts.render.bhRepeat=n` | `BlackHoleLens` draws each hole n times inside its timer section: `(t(n) - t(1)) / (n - 1)` is a draw's marginal (throughput) cost, without the latency a timer query serialises round one small draw (which dominates the single-draw number for anything under about 100 px). The picture is wrong in such a run. |
| `-Dbts.render.bhDepthRepeat=n` / `-Dbts.render.bhDepthDebug=true` | `BlackHoleLens`'s depth pass (review of R-16) drawn n times inside the timer section (its marginal cost as `bhRepeat`; 0 skips it), or drawn in red with colour writes on, to see where it writes depth. |
| `-Dbts.render.eyeRepeat=n` | The Eye star's whole v2 draw runs n times inside its timer section (marginal cost, as `qRepeat`). |
| `-Dbts.render.galSplit=true` | With the GPU timer: the galaxy's backdrop, disc and stars timed in their own sections (`gal.sky`, `gal.disc`, `gal.stars`). |
| `-Dbts.render.qRepeat=n` | The quasar's whole v2 draw runs n times inside its timer section: the marginal cost per quasar, as `bhRepeat` for the Kerr. |
| `-Dbts.render.glcheck=true` | The GL error check outside a dev environment. |
| `-Dbts.render.leakcheck=true` | `GlStateCheck` (R-16): the GL state is read before and after every renderer's draw (the outermost `GpuTimer` section) and every difference is logged once and counted per renderer and state (program, active unit, textures on units 0-7, buffers, vertex arrays, framebuffers, blend, depth, alpha, cull, lighting, fog, colour mask, polygon offset, client and generic vertex arrays, matrix mode, stack depths and matrices, current colour, line width, point size, the lightmap coordinates). The harness writes the result per shot (`leaks` in `fps.tsv`). A check run, never a timing run. |
| `-Dbts.render.forceCore=true` | GT's shader profile becomes `ANGELICA_CORE` before our first bake, so a client without Angelica draws every program through its `#version 330 core` variant and GT's core meshes (R-16). |
| `-Dbts.render.fakeShaderpack=true` | `ShaderpackProbe` answers "a pack is in use" (no screen-copy lensing). The harness case token `pack` does the same per case. |

With `-Dbts.rendertest.gputime=true` the GPU timer also counts the bytes the render thread allocates inside each
renderer's section (`AllocProbe`, HotSpot's per-thread counter, its own cost subtracted): `gpu_detail` reads
`key=gpu_ms/cpu_ms/bytesB` per frame.

## The performance scene (R-16)

`-Dbts.rendertest.only=scene` shoots `rendertest/RenderScene`: a Kerr T2 at 512 SM, the Homogeny (T3, mixing), an
Eye T8 in the Galactic Merger and a 4,096 SM quasar frozen 25 ticks into an eruption, built close together on site
`SCENE` (x 10,000) so the `tilt` view (found by a search: every render centre in the frame, within 235 blocks) shows
all four. Each case carries a quality token: `off` (every big render skips its draw: the baseline), `low`, `medium`,
`high`, `high16` (16 objects allowed at L0), `pack` (shaderpack probe yes), `fail` / `recover` (every program fails
its bake, then bakes again: `BTSShaders.debugFailAll`), `glerror` (an invalid GL call inside each checked draw). Views:
`tilt`, `over`, `qring`, `klevel`, `ebowl`, `hud` and `inv` (the HUD, the hand item and the creative inventory with
NEI over the scene), and the LOD walks `lodk:<d>`, `lode:<d>`, `lodq:<d>`. `FrameProbe` adds whole-frame numbers to
`fps.tsv`: frames, FPS from the frame interval (the harness holds the frame cap and vsync off), mean / p50 / p95 / p99 /
max frame ms, the render tick's CPU ms, the GPU ms between two `GL_TIMESTAMP` queries round the render tick, KB
allocated per frame.
